# Project navigation (#27)

Tabs are grouped by **project = (profile, folder)**: `src/app/project-nav.js` (`window.OMP_PROJECT_NAV`, regression `test-project-nav.mjs`) is the single definition, shared by the tab bar (`design/tab-group-chip.jsx` renders a group of ≥2), the sidebar (`design/project-sidebar.jsx`), the history panel's per-project filter chips (`sessionProjects`, #35 — saved sessions are already one profile's, so the folder alone is the key) and `live.js`'s focus-existing lookups. Paths compare via `normPath` (slashes, trailing slash, case only for Windows drive/UNC paths); pathless tabs never group.

- Recent projects live in `<app config>/recent-projects.json` (`src-tauri/src/recent_projects.rs`), one list keyed per entry by profile, capped at 20 per profile, newest first. Disposable data: an unreadable file reads as empty and the next write replaces it; entries whose folder is gone are hidden, not deleted. `recent_projects_touch` canonicalises (`external_open::canonical_folder`), and so does `open_project`'s folder picker — tab paths and recent entries must be in the same form, or a folder picked through a symlink would not match its open tab.
- `live.js` records a recent only after a successful spawn (`_startProjectSession`, and a profile switch's respawn), and keeps `recentProjects` for the *active* profile only (`_syncRecentsProfile` on activation, last-tab close, profile refresh). All recents IPC runs through one queue (`_recentsCall`): the backend's `list` is unlocked, so unordered calls could let a stale list overwrite a newer touch.
- `openSession`/`+`/`Ctrl+T` always spawn. `openProject` (a recent row) and `resumeSession` focus an existing tab first (`findProjectTab` / `findConversationTab`). The latter matches the registry's `sessionFile`, seeded with the resume path and refreshed from `get_state` while the tab is active; `/new` and a profile respawn clear it (`_freshConversationFields`).
