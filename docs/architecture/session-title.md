# Session-title tab rename

RPC-mode omp never titles a session (it pins `PI_NO_TITLE=1`), so `live.js` asks for one: after the first clean exchange it sends the bare `/rename` builtin as a `prompt`, and `session_info_update` renames the tab. The title is refreshed every `REFINE_EVERY_TURNS` terminal `agent_end`s, at most `REFINE_MAX` times. The gates are pure helpers in `src/app/session-title.js` (`window.OMP_SESSION_TITLE`, regression `test-session-title.mjs`); the state lives on the registry entry (`autoRenameArmed/InFlight/Attempt/Turns/Left/SessionId`), plus the snapshotted `lastTurnOk`.

- Fresh and resumed tabs start eligible for an initial title. A non-empty native `sessionName` retires that eligibility before any send, preserving saved manual and automatic names; a resumed named conversation gets no refresh budget because its title source is unknown. A stored folder fallback is not a native title. `/new` and a profile respawn reset to the folder name and re-arm.
- Initial naming stays armed until a title actually arrives. A refused generation or failed IPC hand-off can try again after another successful terminal turn; repeated idle snapshots, failed exchanges and scheduling pauses do not trigger retries. One request stays in flight until its outcome, even across many turns. `autoRenameAttempt` is an identity token that owns a delayed IPC failure and distinguishes an untried conversation from one waiting for new material. Successful initial naming enables the existing bounded refinement cadence; failed initial attempts never exhaust that budget. Aborting an untitled request resets the attempt gate, preserving the existing abort recovery.
- `session_settled` requests a fresh `get_state`, even when no background work was recorded. An `agent_end` snapshot can still report streaming while omp finishes its run; the settled snapshot lets initial naming proceed without waiting for another prompt or tab switch. Naming still goes through the same idle, successful-exchange and single-flight gates.
- Settings → Session "Name tabs automatically" (`autoName`, default on; `docs/architecture/settings.md`) gates both sends: while off, neither the first `/rename` nor a refresh goes out, and the arming state is left as it is, so switching it back on resumes for tabs still armed. A manual rename is unaffected.
- A user-typed `/rename` (`isManualRename`: the name ends at whitespace **or `:`**, like omp's `parseSlashCommand`) retires everything for good — omp's `user` title source only shields against `auto` writes, and our bare `/rename` writes as `user` too.
- `autoRenameInFlight` gates swallowing the builtin's outcome note (`command_output`, matched by prefix against omp's strings in `slash-commands/builtin-lifecycle.ts`). The note can land turns later, so **nothing may clear the flag on a title seen in `get_state`** — a stale snapshot still carries the old title. It is released by the note, a manual `/rename`, a fresh conversation, the `abort` response (success or not: `abort()` cancels title generation first), a `dropped` journal replay, and an in-process omp session switch (`isRenameStateStale` on `sessionId`, which also retires the budget). `branch`/`fork` (conversation tree) also move the process to a session with a new id, but the tab keeps its name and budget: `_resetForNewFile` drops `autoRenameSessionId` and releases the in-flight flag (its generation belonged to the old session), and `_applyRpcState` binds a budget that is armed or has `autoRenameLeft` but no binding yet to the `sessionId` omp reports — only a *bound* id that later differs counts as a switch.
- `OMP_BRIDGE.abort()` must stay **id-less**: a pending-id match returns from `_handleResponse` before the `abort` branch, so the flag would never be released and initial naming never re-armed.
- **Manual rename (#32)** is the same builtin: `OMP_BRIDGE.renameSession(id, title)` (tab double-click, pencil in the group dropdown and the sidebar; inline editor `design/rename-field.jsx`) sends `/rename <title>` as an id-correlated `prompt` — omp runs builtins before its streaming check, so it works mid-turn. It activates a background tab first (only the active tab's frames are processed), retires auto-rename via `_disarmAutoRename`, and pushes no bubble or prompt-history entry. Its confirmation is swallowed by **exact** text (`STITLE.manualRename` mirrors omp's `#cleanTitle`, so the note's args match byte for byte) from the entry's `renameNotes` (`STITLE.dropPendingNote`), which a settled response releases — not a timeout, whose frames may still arrive by journal replay; refusals and errors stay visible. `RenameField` commits on blur, so the composer's streaming-end refocus skips when another typing target holds focus.

`test-session-title-bridge.mjs` exercises the real bridge through RPC/IPC fixtures: untitled resume, repeated failures without polling storms, successful-terminal-turn eligibility, delayed outcomes, IPC failure, manual-name protection, the auto-name setting and bounded refinement. A compiled-UI browser smoke verifies a grouped **New conversation** row changing into its generated title after a refused first attempt, without leaking the outcome note into chat.
