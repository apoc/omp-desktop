# Compacted history (#85)

After a compaction omp's `get_messages` (the agent context) starts at the compaction summary, so a tab opened on a compacted conversation (relaunch, launch restore, resume from history) shows only the post-compaction context. In a tab that was open while it compacted, the live pre-compaction entries stay: `mergeTranscript` keeps entries that have no persisted copy. This feature loads the summarized history back from the session file, read-only, above the current transcript, with a divider per compaction. omp's TUI equivalent is `display.collapseCompacted: false`, a TUI-only setting that has no effect in RPC mode.

## Decisions

- **D1 Source: the session JSONL, read in Rust.** New command `session_history` (module `src-tauri/src/session_history/`). The webview never gets raw entries: the command returns only what the transcript renders. omp's `get_entries` is not used. It returns every entry, including tens of MiB of tool results, through the RPC pipe, the event journal (`replay_events`) and the webview.
- **D2 Confinement.** `session_file` must pass the same check as `conversation_tree` (`conversation_tree::validate`, made `pub(crate)`: a `.jsonl` file under the profile's sessions root, symlink escape refused). The profile is resolved through `ProfileStore::resolve_owned` (the `conversation_tree` command shape), and the work runs off the IPC thread (`off_ipc`). A file omp has not written yet returns an empty result.
- **D3 Path.** The current branch is the ancestor chain (`parentId`) of omp's leaf, resolved the way omp resolves it on load (`resolveSessionLeafId`). Take the last entry's `activeLeafId`, or its `id` when `activeLeafId` is absent. A `null` `activeLeafId` means no leaf: the result is empty. An `activeLeafId` that names no entry falls back to the newest entry whose own leaf is itself. Entries off the path (other branches) are never returned. The path walk stops at an id it has already seen, which guards against cycles.
- **D4 Anchor and paging.** Arguments: `sessionFile`, `profile`, `before` (optional number) and `limit` (u32, clamped to 1..=500).
  - `before` is omp's message `timestamp` (ms) of the oldest user/assistant entry with a `ts` the tab shows. The anchor is the last path entry whose `message.timestamp` equals it, and the result covers only path entries strictly before the anchor.
  - With no `before`, the result covers the whole path.
  - When `before` matches no path entry, the result is `{ items: [], more: false }`.
  - The result is the newest `limit` *display items* of that range, in path order. `more` says whether an older display item exists before the returned slice.
- **D5 Items (the wire contract).** Items are shaped like omp `AgentMessage`s so the frontend reuses `adaptAgentMessages` (and its `finalFailures`) unchanged. `timestamp` is always the message's own numeric timestamp, never the entry's ISO string.
  - `message` entry with role `user` → `{ role: "user", timestamp, content }`. `content` keeps only `text` and `image` blocks; a string content becomes one text block. A user message with no text and no image is dropped, not counted.
  - `message` entry with role `assistant` → `{ role: "assistant", timestamp, content, stopReason, errorMessage, errorStatus, provider, model, usage, retryRecovery }`. `content` keeps only `text` and `thinking` blocks; absent fields are omitted. Always returned, because `finalFailures` needs the assistant sequence. It counts as a display item only when it has non-blank text or thinking, or `stopReason === "error"`.
  - `custom_message` entry → `{ role: "custom", customType, timestamp }` (no content). Returned for `finalFailures` boundaries, never counted.
  - `compaction` entry → `{ role: "compactionSummary", timestamp, summary, shortSummary, tokensBefore }`, counted. **Placement:** the item sits immediately before the path entry whose id is its `firstKeptEntryId`, so everything above the divider is what that compaction summarized. When `firstKeptEntryId` is empty or not an earlier path entry, it sits at the compaction's own position.
  - Snapcompact rescue: a `snapcompact` compaction followed on the path by a `snapcompact` compaction whose `parentId` is its id, with the same `firstKeptEntryId` and `tokensBefore`, is skipped (omp's transcript rule).
  - Everything else (tool results, `branch_summary`, model/label/usage entries, …) is not returned. Malformed lines are skipped, as in `conversation_tree/parse.rs`.
- **D6 Frontend state.** Each tab has `olderHistory: { available, loading, error }` in live state. It goes through snapshot and restore like `trimmed`, and `loading` is restored as `false`.
  - `available` is set by each `get_messages`. It is true when the raw context's first message has role `compactionSummary`, `state.trimmed` is false, and the merged transcript's oldest user/assistant entry with a `ts` is one whose message the context returned. A live entry from before the compaction above the copies means the history is already on screen.
  - A load that returns `more: false` sets `available` to false.
  - `room` = `MINIMAP_MAX` − transcript length. The cap stays: loaded entries count toward it, and `_trimMessages` may later cut them like any other head.
- **D7 Loading.** `OMP_BRIDGE.loadOlderHistory()` invokes `session_history` with the tab's registry `sessionFile` and profile, `before` = the anchor `ts` (none when no entry has one) and `limit` = room.
  - Items are adapted in segments: `adaptAgentMessages` per run of non-compaction items, and `compactionSummary` → `{ kind: "compact", status: "done", shortSummary, summary, tokensBefore }` (the existing `CompactRow`). Both go in at index 0.
  - The result applies only if the same tab is still active and its anchor is unchanged; otherwise it is dropped and `loading` is cleared. Room is recomputed at apply time; when it shrank, only the newest entries that fit go in, and `available` stays true.
  - Prepending shifts index-keyed live state (`activeToolCards`), the same way `_trimMessages` shifts it.
  - Loaded entries carry their `ts` and have no copy in the context, so the next `mergeTranscript` keeps them in place. Divider rows carry no `ts`.
- **D8 UI.** While `available && room > 0`, a row at the top of the chat says the earlier history was compacted, with a "Show earlier history" button. It reads "Loading…" while loading, and on an error it shows the error with a retry button.
- **D9 Setting.** Settings → Session: "Show compacted history" (tweak `showCompactedHistory`, default off; listed in `OMP_SESSION_PREFS` KEYS). When it is on, a `get_messages` that sets `available` starts one load by itself. The row and the button work with the setting off.
- **D10 Scope.** `get_messages` keeps dropping omp's leading `compactionSummary` message: rendering it there would need a merge key against the live `/compact` row, whose response carries no timestamp. The divider comes only from loaded history. Remote (phone) views show whatever the transcript holds. No change to the 169-entry cap. omp's version floor is unchanged: no new RPC.
