# Subagent manager

Replaces the old prototype-only "peer session" split/rail widgets (removed). omp streams subagent activity over RPC once subscribed: `set_subagent_subscription` (`off | progress | events`), frames `subagent_lifecycle` / `subagent_progress` / `subagent_event`, plus `get_subagents` (running agents only) and `get_subagent_messages` (tails an agent's session file by byte offset). `src/app/subagents.js` is the pure reducer over those frames (regression: `test-subagents.mjs`); `live.js` keeps its result in `state.subagents`, snapshotted per tab like the transcript.

- omp's registry *deletes* an agent on its terminal status, so the desktop keeps finished agents itself until the session changes (`_resetSessionVars`). Don't replace the local copy with `get_subagents`.
- `_initFetch` re-asserts the subscription (a respawned process starts at `off`) and calls `get_subagents` on every activation — but drops its post-negotiate batch if a tab switch started meanwhile (`_switchGen`), since it would still address the tab being left; `mergeSnapshots` marks agents that were live locally but are no longer listed as ended with `unknownOutcome` (finished outside the journal replay window).
- A dead process (the `agent://exit` listener, or a startup error surfaced on activation) ends its live agents via `mergeSnapshots(…, [])` — nothing else ever would.
- Receive time is not start time: journal-replayed frames arrive late, so `applyProgress` pulls `startedAt` back to `now - progress.durationMs`.
- `events` is the expensive level: only while an agent the manager actually holds is on screen in the inspector (`useSubagentManager` derives `inspecting` from the resolved agent, not the raw id → `OMP_BRIDGE.setSubagentInspecting`). `_switchToSession` downgrades the process being left before `activeSessionId` moves, but leaves the flag to the UI.
- The Rust bridge only forwards allowlisted command types (`ALLOWED_COMMAND_TYPES` in `src-tauri/src/agent/mod.rs`) — a new RPC command in `live.js` must be added there too, or `send_command` rejects it before it reaches omp.
- The manager pane *is* the `layout: "split"` column (`.window.is-split`, the `layout` tweak, also Settings → Layout); open/close goes through `setTweak`. Transcripts (`state.subagentTranscripts`) are ephemeral — not snapshotted, dropped on tab switch, refetched on demand; a response landing after a switch is discarded.
- **Steer and stop** (`design/subagents/subagent-controls.jsx`, live only while the inspected agent is `running`; after that it stays only to hold text that never got through): the message box sends on the Settings → Composer send key (`isSubmitKey(e, submitKey)`, passed down from `app-live.jsx` through `SubagentPane` and `SubagentInspector`). `OMP_BRIDGE.steerSubagent` sends `steer_subagent`, `cancelSubagent` sends `cancel_subagent`, both id-correlated. omp runs a steered message through the subagent's own `prompt()` (slash commands and templates run *inside* the agent, no images) and holds the reply until the agent accepted it, so a timeout is reported as "may still arrive", not as a refusal. The message reaches the event stream as a `user` `message_end`; `summarizeEvent` shows only `attribution: "user"` ones — the task prompt and omp's reminders are `agent`-attributed. A stop is confirmed in place first; `cancelled: false` means the agent was no longer running, and the record ends with omp's `aborted` lifecycle frame, never locally.

## Native agent context

The **Context** card combines aggregate model-window usage with a read-only inventory, not a chat event stream. Its inspector preserves **Used this session**, **Project skills**, **Shared skills**, **OMP / current profile**, **Other sources**, and **Loaded instructions**. Catalog membership is availability, not use or proof of current retention. Only successful native skill reads and user-attributed `skill-prompt` invocations populate session use; automatic injections, failed reads and unproven mixed batches do not. Origin badges describe the observed source. System prompt sections are separately inspectable. Subagent context is agent-scoped; execution controls stay in the dedicated manager and child windows are never summed into the main gauge.

The desktop embeds a read-only omp observer in an exclusively created private runtime directory and passes its absolute path through `--extension`, before normal argv and the final browser config. It appends local `omp-desktop:agent-context` custom entries, never model messages. Native task children inherit it. Observations include prompt sections, the native skill catalog, tool definitions/provenance, model/usage and optional asynchronous memory status. Prompt, skill and tool/schema payloads are separately bounded to 512 Ki UTF-16 units, with truncation explicit (4096 catalog entries, 2048 tools). Session/branch/compaction events force a snapshot; other unchanged observations deduplicate. Full prompt text stays in local native metadata and is never published to phones.

Origins describe the observed location, not authorship. `getCommands()` currently omits skill-loader provider metadata, so explicit native project location wins; otherwise the observer matches the process's `PI_CODING_AGENT_DIR`, known home roots, and current-project/ancestor paths with directory-boundary checks. **Shared** means home `.agent/skills` or `.agents/skills`; **OMP / current profile** means the configured OMP agent directory or its home config root (`PI_CONFIG_DIR`, default `.omp`). Project-local `.omp/skills` remains **Project**, not OMP/global. Recognized other home roots name Claude, Codex or OpenCode; unmatched paths remain **Other**. These rules use the original catalog path, not a symlink target, and never label a skill bundled. Older observations retain recorded project scope but otherwise fall into Other with source details explicitly unavailable. An invocation whose recorded path differs from the current same-name skill is not relabeled with the replacement's provenance.

The context model keeps ancestry plus context observations, not ordinary message/tool-output bodies. Main-agent reads share the activation's raw-entry request with unanswered-question recovery, then use native `since` cursors. Subagent lifecycle/progress changes coalesce incremental `get_subagent_messages` byte tails with bounded concurrent reads: no polling loop and no permanent `events` subscription. Tab activation, conversation and subagent session-file ownership guard every result. Context is snapshotted per tab; a reissued child id with a different session file starts empty. A native byte-tail reset discards the old child's observations.

Context observation never inserts messages, minimap cells or legend entries and never consumes chat scrollback. The rail keeps the usage/target interaction compact; **Inspect context** opens searchable grouped lists, an optional token breakdown and one detail pane, with a list/detail Back action on narrow windows. Per-tab search, filtering, group expansion and selected agent survive closing/reopening and tab switches; stale source selections clear. Escape/Close restores focus. Skill previews retain source paths, matched roots and classification explanations. Instructions and memory blocks use observed prompt text, never arbitrary renderer-selected file reads.

Current native `get_state` exposes the main model, context usage, system prompt and active tool schemas. Its in-memory overlay wins over older persisted observer records, including after an idle model switch. Missing fields on older native versions remain unavailable. MCP definitions are grouped only by explicit server metadata; provenance can establish MCP origin even when the native tool API omits the server name. Call history keeps bounded branch-scoped identity/outcome metadata, not arguments/results, and jumps only to cards still present in chat. Memory status is read without search/save, never awaited on provider dispatch; generation, model, file and leaf guards reject stale asynchronous completions. A disabled backend is distinct from unavailable details. Only recognized observed memory prompt blocks are shown.

The public native interface supplies aggregate usage, which may combine provider anchors and local estimates, but no authoritative category token attribution or retained skill/call ids. The inspector's secondary **Token breakdown** disclosure fills missing categories with **≈ local text estimates** (UTF-8 bytes divided by four): System prompt excludes observed `<skills>` catalog sections, Skills counts those sections, and Tool definitions counts active names/descriptions/schemas only (zero when the model explicitly defers schemas server-side). Loaded skill bodies are not counted again as catalog tokens. Messages is the non-negative remainder of native aggregate usage; approximation differences can make the components exceed the aggregate. Missing/truncated source data remains unavailable, never a partial total presented as complete. Retained ids remain unknown; historical use is never relabelled retained. Compaction clears stale current details while preserving session-use history. Manual compact responses, auto-compaction start/end, model changes and config updates invalidate pending accounting/inventory reads. Correlated state requests are scoped to tab, conversation, activation, revision and request order; timed-out/replayed older responses cannot overwrite fresh state. Capacity and percentage are recomputed from native current-window data, with no fabricated 200k default. A failed refresh shows unavailable usage rather than old numbers.

Skill previews use `agent_context_read_skill(sessionId, agentId, name)`. The renderer supplies no filesystem path. Rust records only correlated native main/subagent observation responses (including protocol-v2 chunks), validates active ancestry and a per-spawn observer epoch, and resolves the name from that process's observed catalog. Old-process snapshots cannot grant file access. The file must remain within its pinned canonical skill directory; replaced symlinks, unknown names, ended processes, missing files and invalid UTF-8 return errors. Reads run off the IPC thread and stop at 1 MiB, with truncation explicit. A human preview never sends an agent prompt, invokes a tool, or marks the skill as used. The existing history boundary is unchanged: finished agents remain known for the current conversation/tab lifetime, not as an archived roster after app restart; previews require a current-process catalog.

Regression coverage includes successful/failed reads, autoload exclusion, source separation/provenance, branch/owner isolation, bounded snapshots, MCP identity/outcomes, compaction history versus retention, asynchronous memory races and the current-RPC-over-old-observation rule. Context-usage regressions exercise manual/automatic compaction, delayed pre-compaction responses, idle model switches and missing capacity. Native scoped-preview tests cover epochs, ownership, ancestry, symlink changes and UTF-8/size limits. A compiled inspector smoke uses real isolated native snapshots: a 200k-to-1M model switch changes 60k usage from 30% to 6%; reopening a persisted compaction reduces usage to 7358 tokens. Browsing/search, source preview, stale selection clearing, call navigation, controlled-state remount and narrow Back navigation were exercised with additional inventory fixtures; no model prompt was sent.

The card's policy controls are separate from this read-only inventory. A second private native extension exposes only allowlisted compaction settings through an epoch-specific local command; it uses native profile persistence and session-branch metadata for explicit conversation overrides. It registers no pre-compaction hook and does not schedule maintenance. Effective settings, stale-edit guards and the shared Settings editor are described under [Native context policy](settings.md#native-context-policy).
