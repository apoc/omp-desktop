## The settings app tab

- State `stab = { open, active, section }` in `app-live.jsx` through the pure `OMP_SETTINGS_TAB` (`initial`, `open(state, section?)`, `close`, `selectProject`, `setSection`, `cycle`). Never persisted: a launch starts closed. `close` resets the section to `appearance`.
- Not a session: no omp process, not in `sessionRegistry`, `open-tabs.json` or the project sidebar, not draggable. `TabBar` (`design/chrome.jsx`) pins it after the project tabs (cog, "Settings", a chip with `modifiedCount("all", t, keyOpts)`, hidden at 0, ×; middle-click closes). While it is active, `activeId` is `null` for the tab bar and sidebar; the omp tab stays `activeSessionId` and the bridge keeps following it, so closing or leaving settings returns to it.
- Host: `<div className="st-host" hidden={!stab.active}>` inside `.stage`, mounted while `stab.open`. Behind a project tab the page stays mounted (search, section and scroll kept) with the last ctx copied as `active: false`; the ctx is rebuilt only while the tab is active, so streaming frames re-render nothing there.
- Open/activate: toolbar cog (`Toolbar` `settings.onOpen`, pressed while `settings.active`), `desktop.settings.open` (`ctrl+,` / `super+,`, not `fromGuest`), `/settings` (desktop-local, shadows omp's own `/settings`; `/tweaks` is gone, no alias). `desktop.shortcuts.open` (`Ctrl+/`) and `/shortcuts` open section `shortcuts`.
- Leaving: any omp tab activation (pick, open, restore, i.e. an `activeSessionId` change) runs `selectProject` (open, inactive). `desktop.tab.close` (Ctrl+W) closes the settings tab while it is active, else the omp tab. `desktop.tab.next` / `prev` use `cycle(stab, sessionIds, activeId, dir)`: settings is the last stop while open.
- `app.interrupt` never fires while `stab.active`. The page listens on `window` in the capture phase, only while active and only for keys aimed at the page (dialogs on top handle their own): Escape is `preventDefault`ed (the keymap skips default-prevented events) but not stopped; it clears the search unless an element marked `data-st-esc` exists (an open row menu, the shortcut recorder), which handles Escape itself. While such an element exists the page's other keys are left to it too. Ctrl/⌘+F focuses the search; ←/→ outside text fields switch sections. Activating the tab focuses the search field, so keys never reach the hidden composer. A section change (including opening on one, e.g. Ctrl+/) clears the search. Leaving the tab ends shortcut recording.

## Schema (`OMP_SETTINGS`)

- `SECTIONS` in order: appearance, layout, chat, composer, rail, terminal, browser, agent, session, remote | approvals (`sep: true`), shortcuts. Each has `id`, `icon`, `title`, `blurb`, `groups` (`name`, optional `src` file chip, `rows`).
- Row kinds: `tweak` (one `TWEAK_DEFAULTS` key; `type` toggle | seg | slider | themes | swatches; rendered by `page.jsx`) and `custom` (`id` `custom:<type>`, rendered by `window.OMP_SETTINGS_ROWS[type]` as `<Comp row ctx query modified onReset />`, showing the schema row's `label` and `desc` plus runtime text of its own; `version` shows runtime text as its desc, `shortcuts` only its editor). Custom renderers register from `rows-appearance.jsx` (`projectAppearance`), `rows-layout.jsx` (`widths`, `widgets`), `rows-programs.jsx` (`shell`, `terminalHeight`, `chromium`), `rows-agent.jsx` (`startupProfile`, `goalContinue`, `autoCompaction`, `autoRetry`), `rows-session.jsx` (`version`), `rows-remote-server.jsx` (`remoteServer`, `remoteCert`), `rows-remote-phones.jsx` (`remotePair`, `remoteDevices`, `remotePush`), `rows-approvals.jsx` (`approvalMode`, `approvalRules`) and `shortcuts-editor.jsx` (`shortcuts`). Both remote row families use the single shared listener, queue and controls in `rows-remote-shared.jsx`.
- A custom row names the tweak keys it owns (`keys`, or `keyPrefix` + `prefixDefault` for `widget:*`), so its changes count in badges and resets. With `opts.prefixKeys` (app-live passes the rendered plugin and extension switch keys as ctx `keyOpts`) only those prefix keys count, so a stored key of a removed plugin never does. Rust-backed rows own none and never count; they show their reset without the changed dot (`SettingsRow resettable`). `projectAppearance` owns none either: it never counts in badges or section reset, but shows its own changed dot and reset for the rendered project's entry.
- Helpers: `rows`, `value` (fold modes resolved, numbers clamped), `clamp`, `visible` (a row's own `visibleIf`: `collapseAfter` only while a fold mode is `auto`), `isModified(row, values, opts?)` (accent compares with the current theme's own, `themeAccent`, through `OMP_ACCENT.sameColor`), `resetRow(row, values, opts?)`, `modifiedCount(section | "all", values, opts?)`, `resetRows(rows, values, opts?)` and `resetEdits(section | "all", values, opts?)` (rows see earlier edits, so a theme reset settles the accent), `search(query, values)` (label + desc + `kw` + runtime `moreKw`, case-insensitive, grouped `Section › Group`, per-section counts; the shortcuts row matches every action label and id). Bounds of `collapseAfter` / `promptHistoryLimit` / `pasteCollapseLines` and the fold modes are read late from `OMP_COLLAPSE` / `OMP_PROMPT_HISTORY` / `OMP_SESSION_UI`.
- Rendering: search hits are highlighted by splitting text into nodes and `<mark>`; backticks in a schema `desc` become `<code>`; no HTML strings are injected. Sliders commit on release. Picking a different theme resets `accent` to the theme's own; picking the current one again does nothing. Badges show changed counts, or match counts while searching. The footer resets the section, or while searching only the matched rows ("reset matches to defaults").

## Behaviours

`live.js` reads `restoreTabs`, `confirmBusyClose`, `autoName`, `showCompactedHistory` at load (`PREFS.fromTweaks(OMP_TWEAKS_STORE.read(), TWEAK_DEFAULTS)`: a missing or non-boolean value is the default); `app-live.jsx` keeps them current through `OMP_BRIDGE.setSessionPrefs` (only changed keys act).

- **restoreTabs** (default on). Off: `_restoreOpenTabs` opens nothing and leaves `open-tabs.json` as it is; arming adopts the empty layout as written, so the file is first rewritten at the first real tab change (`reopening-tabs.md`).
- **confirmBusyClose** (default off). On, closing a busy tab (`OMP_TURN_STATUS.isBusyRunState` over its guard `runState`: running, retrying, waiting-user, background — for a background tab the raise-only union of its frozen state and the tracker, `turn-status.md`) asks first: the tab bar's close goes through `closeSessionGuarded` (`closeSession` stays unconditional). Quitting with busy tabs asks too. Both re-read the tracker (`attention_snapshot`) before deciding. Rust's `CloseGuard` holds two flags, set together by `set_close_guard { armed, enabled }` from `_syncCloseGuard` on every notify (tracker payloads included; only a change is sent): `armed` exactly while `closeGuardArmed` (setting on and a tab busy in the webview's view), `enabled` while the setting is on. `holds_close` holds the main window's close when `armed`, or when `enabled` and the tracker snapshot (`remote::tracker`) has any session busy, asking or holding background work — so a turn a background tab started after the webview last re-armed is held too, with no gap between the tracker change and the re-arm (#89). Holding, `handle_run_event` prevents the main window's `CloseRequested` and an `ExitRequested` without code, and emits `window://close-requested`; `live.js` answers with `_requestQuit`. An `ExitRequested` is held only while the main window still exists (`holds_exit`): the last window's own close also ends in one, and with the window gone nobody could confirm, so the app would stay up with no window. Our own close buttons call `_requestQuit` directly. A confirmed quit clears both flags, then closes the window, so the exit takes the usual `kill_child_processes` path. The dialog is `design/confirm-close.jsx` over the snapshot's `closeConfirm` (`tabCloseConfirm` / `quitConfirm` shape); `resolveCloseConfirm(ok)` answers it; a newer request replaces one on screen (which resolves false).
- **autoName** (default on). Off: the auto `/rename` and its refreshes are not sent; the arming state is untouched, so turning it back on resumes for tabs still armed. A manual `/rename` is unaffected (`session-title.md`).
- **showCompactedHistory** (default off). On, a `get_messages` whose context opens with a compaction summary the transcript does not show yet loads that history once by itself (`_loadOlderHistory`, `compacted-history.md` D9). Off, the row at the top of the chat still loads it on request.
- **notifySound / soundAttention / soundFinished / soundVolume** (Settings → Session → Sounds; defaults `off`, `bell`, `chime`, 60; `notification-sounds.md`). `live.js` keeps them as `soundPrefs` next to `sessionPrefs`: `OMP_NOTIFY_SOUND.prefsFrom(OMP_TWEAKS_STORE.read(), TWEAK_DEFAULTS)` at load (an invalid mode, sound id or volume reads as its default) and `setSessionPrefs` recomputes it from the validated prefs plus whatever keys it receives, so a partial object keeps the rest. `_applyAttention` asks `cue` for each tracker snapshot. `notifySound` is a seg row (`off` | `background` | `always`); the `sounds` custom row (`design/settings/rows-sounds.jsx`, owns `soundAttention` and `soundFinished`) shows one line per cue: a seg of `none` plus the catalogue, ▶ preview, its own reset; `soundVolume` is a 0–100 slider (step 5). The `sounds` and volume rows show only while the mode is not `off` (`visibleIf`; an invalid stored mode counts as `off`, like `prefsFrom`). A preview plays regardless of the mode.
- **Auto-compact context / Retry failed requests** (Settings → Agent → "omp behaviour"). omp's own `compaction.enabled` and `retry.enabled` (both default `true` in omp), not tweaks: the rows are custom rows (`autoCompaction`, `autoRetry` in `design/settings/rows-agent.jsx`, searchable like any row, owning no tweak key) over the same plumbing as the goal row. Each reads omp's value of `ctx.goal.profileId` (the rendered tab's profile) through `useOmpSetting` (`app/use-omp-setting.jsx`, over the generic `useOmpFlag` the goal hook builds on too) → `OMP_BRIDGE.ompSetting` / `setOmpSetting` → the `omp_setting_get` / `omp_setting_set` commands, which take a closed `setting` (`autoCompaction` | `autoRetry`, never an omp key) and run `omp [--profile=<id>] config get|set <key>` through `omp_config.rs` (`resolve_owned` first, `async` + `spawn_blocking`, one lock for every `omp config` run). A set writes only when the effective value changes and answers with the value re-read. Auto-compaction is two keys: omp compacts only while `compaction.enabled` is on AND `compaction.methodOrder` is non-empty (a legacy `compaction.strategy: "off"` becomes `[]`), so the switch reads both under one lock and shows `enabled && !methodOrder.is_empty()`; turning it on sets `enabled` when needed and runs `omp config reset compaction.methodOrder` when the order is empty (what omp's own setter does), turning it off writes only `enabled: false`. The scope is the profile's config: `omp config` runs in the desktop's own working directory, so a tab project's `.omp/config.yml` is neither read nor shown. The description names the profile; while the read runs the control shows "reading…", a failed read or write shows omp's reason. Running tabs of the profile pick a change up through omp's config watcher (omp 18.3.1+): the desktop sends no `set_auto_compaction` / `set_auto_retry` frame, so there is no per-process override that omp's config could not undo, and neither command is in `ALLOWED_COMMAND_TYPES`. The old desktop-only `localStorage` keys `autoCompaction` / `autoRetry` are ignored and not migrated: a switch the user had turned off there shows omp's value now.
- **submitKey** (`enter` | `ctrl+enter`). `window.isSubmitKey(e, pref)` (`app/constants.js`) for the multi-line fields only: composer, ask-bubble editor, subagent steer box. `enter`: Enter without Shift sends. `ctrl+enter`: Ctrl/⌘+Enter (no Shift/Alt) sends, plain Enter is a newline; the composer checks the send chord before the `app.message.followUp` match. The slash menu's Enter still picks a command. Single-line inputs (rename, profile name, ask-dialog single-line) keep `isSubmitEnter`. The composer hint follows the setting.
- **dictationSend** (default off). `app-live.jsx` `requestDictationAction("stop")` passes it as `OMP_BRIDGE.dictationStop({ send })`; `live.js` tags that capture's completion `send: true` (`_dictationSendCapture`). Stops the bridge makes itself (tab switch, Settings, close, respawn) never pass it. The composer appends the text as usual and, while that tab is shown, sends the draft through `sendWith(onSend)` once the rendered draft ends with the dictated text.
- **dictationAutoStop** (`0` = off | 1.5 | 2 | 3 | 5 s, default 3, room for a thinking pause). `OMP_LIVE_VOICE.DICTATION.autoStopDelay(dictation, seconds)` is the timer: only while the capture is `recording` and has text (no timer before the first words), re-armed by every text change (omp sends new text only for sound its endpointer takes as speech, so the app needs no audio levels). When it fires, `app-live.jsx` calls `requestDictationAction("stop")`, the user's own stop, so `dictationSend` applies.
- **voiceSpectrumBands** (16 | 32 | 48 | 64 | 96 | 128, default 64). Bars of the composer's microphone equalizer, passed to Rust as `voice_spectrum_start { bands }` (`voice-spectrum.md`); a change while it runs restarts the reader with the new count. The Composer section's **Voice** group holds it with `dictationSend` and `dictationAutoStop`.
- **pasteCollapseLines** (2–50, default 5). `OMP_SESSION_UI.shouldCollapsePaste(raw, maxLines)`; the 500-character cap stays.
- **followOutput** (default on). `OMP_SCROLL_PIN.afterOutput({pinned, follow, repin}, metrics)`: off, new output never scrolls; content pushed past the bottom unpins ("Jump to latest" shows). A sent prompt, a transcript reset and the first render still jump to the latest.
- **terminalScrollback** (1000 | 5000 | 10000 | 50000, default 5000). `OMP_TERMINAL_XTERM.scrollbackLines(pref)` (0–100000) at xterm creation; `useTerminal` applies a change to existing terminals.
- **defaultSide** (`rail` | `tree` | `browser`). `app-live.jsx` seeds a tab's side column with `OMP_SESSION_UI.seedEntries` the first time its id is seen (`seenSideIds`; restored tabs count as new); `rail` stores nothing. Changing the setting never moves open tabs.
- **Accent.** `useThemeEffect` (`app/use-bridge-snapshot.jsx`) clears `--accent`, `--accent-soft`, `--accent-glow`, `--accent-deep`, then, when the accent differs from the theme's own, sets all four from `OMP_ACCENT.accentTokens` (soft 12% / glow 45% alpha as `rgba()`, deep = 25% black; xterm reads `--accent-soft` uncomputed, so no `color-mix()`).
- **Project colours.** The `projectAppearance` tweak maps a normalised project folder (`OMP_PROJECT_NAV.normPath`; tab paths reach the frontend canonicalised in Rust) to `{theme?, accent?}`. The rendered tab's project wins in `useThemeEffect` (`app/project-appearance.js` `resolve`), and the global `theme`/`accent` stays the fallback; the sidebar tints a project's folder glyph with its accent. Settings → Appearance → Project colours (`custom:projectAppearance`, `design/settings/rows-appearance.jsx`) owns no tweak keys, so the section badge and section/search Reset skip project colours entirely; the row's own changed dot and `↺ reset` cover only the rendered tab's entry, and reset clears just that entry. It edits only that entry: picking a theme stores it with the theme's own accent, as the global Theme row does, and picking the theme the project already has does nothing, so a custom accent survives; `Global` clears both, and the accent swatches set the accent alone. Terminals follow the resolved palette: `app-live.jsx` passes the resolved palette (`OMP_PROJECT_APPEARANCE.resolve`) to `useTerminal`, which re-themes when its theme or accent changes. Tests: `test-project-appearance.mjs`.
- **Updates.** The `version` row shows the version and last check, "Check now" (`updater.check`) and the skipped release with "Clear skipped" (`updater.clearSkipped`).
- **Approvals.** The `approvalMode` row renders the same `ApprovalModeSection` as the approvals panel; `approvalRules` shows the rule count and opens the panel.
- **Shortcuts.** `shortcuts-editor.jsx` is the rebinding editor (formerly the shortcuts modal): rebind, add a chord, clear, reset to default; rows from omp's `keybindings.yml` can be overridden too; the source chip shows where a binding comes from.
- **Changes.** The `showChanges` rail toggle (default on) shows the Changes card; off also cancels its reads and turns Auto-fix off in every tab, and turning it back on never re-enables Auto-fix. The card, its GitHub lookup and Auto-fix: `pr-automation.md`.
- **locale** (`auto` | `en` | `zh`, default `auto`). The interface language of the app's own controls (`i18n.md`): `app/i18n.js` reads the stored value at init, and `app-live.jsx` applies a change in a layout effect, subscribed through `OMP_I18N.useLocale()`, so the tree repaints before the next paint. Strings are keyed by their English source; a missing entry falls back to English. The desktop chrome is translated (`app/i18n-zh.js`), including this page and its schema, and `search()` indexes both languages (labels, descriptions and shortcut action names). omp's own text (replies, tool output, asks, model names) is not translated.
