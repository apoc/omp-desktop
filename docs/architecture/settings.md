## The settings app tab

- State `stab = { open, active, section }` in `app-live.jsx` through the pure `OMP_SETTINGS_TAB` (`initial`, `open(state, section?)`, `close`, `selectProject`, `setSection`, `cycle`). Never persisted: a launch starts closed. `close` resets the section to `appearance`.
- Not a session: no omp process, not in `sessionRegistry`, `open-tabs.json` or the project sidebar, not draggable. `TabBar` (`design/chrome.jsx`) pins it after the project tabs (cog, "Settings", a chip with `modifiedCount("all", t, keyOpts)`, hidden at 0, ×; middle-click closes). While it is active, `activeId` is `null` for the tab bar and sidebar; the omp tab stays `activeSessionId` and the bridge keeps following it, so closing or leaving settings returns to it.
- Host: `<div className="st-host" hidden={!stab.active}>` inside `.stage`, mounted while `stab.open`. Behind a project tab the page stays mounted (search, section and scroll kept) with the last ctx copied as `active: false`; the ctx is rebuilt only while the tab is active, so streaming frames re-render nothing there.
- Open/activate: toolbar cog (`Toolbar` `settings.onOpen`, pressed while `settings.active`), `desktop.settings.open` (`ctrl+,` / `super+,`, not `fromGuest`), `/settings` (desktop-local, shadows omp's own `/settings`; `/tweaks` is gone, no alias). `desktop.shortcuts.open` (`Ctrl+/`) and `/shortcuts` open section `shortcuts`.
- Leaving: any omp tab activation (pick, open, restore, i.e. an `activeSessionId` change) runs `selectProject` (open, inactive). `desktop.tab.close` (Ctrl+W) closes the settings tab while it is active, else the omp tab. `desktop.tab.next` / `prev` use `cycle(stab, sessionIds, activeId, dir)`: settings is the last stop while open.
- `app.interrupt` never fires while `stab.active`. The page listens on `window` in the capture phase, only while active and only for keys aimed at the page (dialogs on top handle their own): Escape is `preventDefault`ed (the keymap skips default-prevented events) but not stopped; it clears the search unless an element marked `data-st-esc` exists (an open row menu, the shortcut recorder), which handles Escape itself. While such an element exists the page's other keys are left to it too. Ctrl/⌘+F focuses the search; ←/→ outside text fields switch sections. Activating the tab focuses the search field, so keys never reach the hidden composer. A section change (including opening on one, e.g. Ctrl+/) clears the search. Leaving the tab ends shortcut recording.

## Schema (`OMP_SETTINGS`)

- `SECTIONS` in order: appearance, layout, chat, composer, rail, terminal, browser, agent, session, remote | approvals (`sep: true`), shortcuts. Each has `id`, `icon`, `title`, `blurb`, `groups` (`name`, optional `src` file chip, `rows`).
- Row kinds: `tweak` (one `TWEAK_DEFAULTS` key; `type` toggle | seg | slider | themes | swatches; rendered by `page.jsx`) and `custom` (`id` `custom:<type>`, rendered by `window.OMP_SETTINGS_ROWS[type]` as `<Comp row ctx query modified onReset />`, showing the schema row's `label` and `desc` plus runtime text of its own; `version` shows runtime text as its desc, `shortcuts` only its editor). Custom renderers register from `rows-layout.jsx` (`widths`, `widgets`), `rows-programs.jsx` (`shell`, `terminalHeight`, `chromium`), `rows-agent.jsx` (`startupProfile`, `goalContinue`), `rows-session.jsx` (`version`), `rows-remote-server.jsx` (`remoteServer`, `remoteCert`), `rows-remote-phones.jsx` (`remotePair`, `remoteDevices`, `remotePush`), `rows-approvals.jsx` (`approvalMode`, `approvalRules`) and `shortcuts-editor.jsx` (`shortcuts`). Both remote row families use the single shared listener, queue and controls in `rows-remote-shared.jsx`.
- A custom row names the tweak keys it owns (`keys`, or `keyPrefix` + `prefixDefault` for `widget:*`), so its changes count in badges and resets. With `opts.prefixKeys` (app-live passes the rendered plugin and extension switch keys as ctx `keyOpts`) only those prefix keys count, so a stored key of a removed plugin never does. Rust-backed rows own none and never count; they show their reset without the changed dot (`SettingsRow resettable`).
- Helpers: `rows`, `value` (fold modes resolved, numbers clamped), `clamp`, `visible` (a row's own `visibleIf`: `collapseAfter` only while a fold mode is `auto`), `isModified(row, values, opts?)` (accent compares with the current theme's own, `themeAccent`, through `OMP_ACCENT.sameColor`), `resetRow(row, values, opts?)`, `modifiedCount(section | "all", values, opts?)`, `resetRows(rows, values, opts?)` and `resetEdits(section | "all", values, opts?)` (rows see earlier edits, so a theme reset settles the accent), `search(query, values)` (label + desc + `kw` + runtime `moreKw`, case-insensitive, grouped `Section › Group`, per-section counts; the shortcuts row matches every action label and id). Bounds of `collapseAfter` / `promptHistoryLimit` / `pasteCollapseLines` and the fold modes are read late from `OMP_COLLAPSE` / `OMP_PROMPT_HISTORY` / `OMP_SESSION_UI`.
- Rendering: search hits are highlighted by splitting text into nodes and `<mark>`; backticks in a schema `desc` become `<code>`; no HTML strings are injected. Sliders commit on release. Picking a different theme resets `accent` to the theme's own; picking the current one again does nothing. Badges show changed counts, or match counts while searching. The footer resets the section, or while searching only the matched rows ("reset matches to defaults").

## Behaviours

`live.js` reads `restoreTabs`, `confirmBusyClose`, `autoName`, `autoCompaction`, `autoRetry` at load (`PREFS.fromTweaks(OMP_TWEAKS_STORE.read(), TWEAK_DEFAULTS)`: a missing or non-boolean value is the default); `app-live.jsx` keeps them current through `OMP_BRIDGE.setSessionPrefs` (only changed keys act).

- **restoreTabs** (default on). Off: `_restoreOpenTabs` opens nothing and leaves `open-tabs.json` as it is; arming adopts the empty layout as written, so the file is first rewritten at the first real tab change (`reopening-tabs.md`).
- **confirmBusyClose** (default off). On, closing a busy tab (`OMP_TURN_STATUS.isBusyRunState`: running, retrying, waiting-user, background) asks first: the tab bar's close goes through `closeSessionGuarded` (`closeSession` stays unconditional). Quitting with busy tabs asks too. `_syncCloseGuard` arms Rust's `CloseGuard` through `set_close_guard` exactly while `closeGuardArmed` (setting on and a tab busy); armed, `handle_run_event` prevents the main window's `CloseRequested` and an `ExitRequested` without code, and emits `window://close-requested`; `live.js` answers with `_requestQuit`. Our own close buttons call `_requestQuit` directly. A confirmed quit disarms the guard, then closes the window, so the exit takes the usual `kill_child_processes` path. The dialog is `design/confirm-close.jsx` over the snapshot's `closeConfirm` (`tabCloseConfirm` / `quitConfirm` shape); `resolveCloseConfirm(ok)` answers it; a newer request replaces one on screen (which resolves false).
- **autoName** (default on). Off: the auto `/rename` and its refreshes are not sent; the arming state is untouched, so turning it back on resumes for tabs still armed. A manual `/rename` is unaffected (`session-title.md`).
- **autoCompaction / autoRetry** (default on). At spawn (`_initFetch`, next to the ask-dialog assert) `set_auto_compaction` / `set_auto_retry` `{enabled: false}` go out only when the setting is off, so with it on omp's own config decides. A change goes to every live process (`_sendToAll`) with the new value either way. Both are in `ALLOWED_COMMAND_TYPES`.
- **submitKey** (`enter` | `ctrl+enter`). `window.isSubmitKey(e, pref)` (`app/constants.js`) for the multi-line fields only: composer, ask-bubble editor, subagent steer box. `enter`: Enter without Shift sends. `ctrl+enter`: Ctrl/⌘+Enter (no Shift/Alt) sends, plain Enter is a newline; the composer checks the send chord before the `app.message.followUp` match. The slash menu's Enter still picks a command. Single-line inputs (rename, profile name, ask-dialog single-line) keep `isSubmitEnter`. The composer hint follows the setting.
- **pasteCollapseLines** (2–50, default 5). `OMP_SESSION_UI.shouldCollapsePaste(raw, maxLines)`; the 500-character cap stays.
- **followOutput** (default on). `OMP_SCROLL_PIN.afterOutput({pinned, follow, repin}, metrics)`: off, new output never scrolls; content pushed past the bottom unpins ("Jump to latest" shows). A sent prompt, a transcript reset and the first render still jump to the latest.
- **terminalScrollback** (1000 | 5000 | 10000 | 50000, default 5000). `OMP_TERMINAL_XTERM.scrollbackLines(pref)` (0–100000) at xterm creation; `useTerminal` applies a change to existing terminals.
- **defaultSide** (`rail` | `tree` | `browser`). `app-live.jsx` seeds a tab's side column with `OMP_SESSION_UI.seedEntries` the first time its id is seen (`seenSideIds`; restored tabs count as new); `rail` stores nothing. Changing the setting never moves open tabs.
- **Accent.** `useThemeEffect` (`app/use-bridge-snapshot.jsx`) clears `--accent`, `--accent-soft`, `--accent-glow`, `--accent-deep`, then, when the accent differs from the theme's own, sets all four from `OMP_ACCENT.accentTokens` (soft 12% / glow 45% alpha as `rgba()`, deep = 25% black; xterm reads `--accent-soft` uncomputed, so no `color-mix()`).
- **Updates.** The `version` row shows the version and last check, "Check now" (`updater.check`) and the skipped release with "Clear skipped" (`updater.clearSkipped`).
- **Approvals.** The `approvalMode` row renders the same `ApprovalModeSection` as the approvals panel; `approvalRules` shows the rule count and opens the panel.
- **Shortcuts.** `shortcuts-editor.jsx` is the rebinding editor (formerly the shortcuts modal): rebind, add a chord, clear, reset to default; rows from omp's `keybindings.yml` can be overridden too; the source chip shows where a binding comes from.
- **Changes.** The `showChanges` rail toggle (default on) shows the Changes card; off also cancels its reads and turns Auto-fix off in every tab, and turning it back on never re-enables Auto-fix. The card, its GitHub lookup and Auto-fix: `pr-automation.md`.
