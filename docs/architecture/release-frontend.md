# Release frontend (`dist/`)

`tauri dev` serves `src/` as is: development React, and every `text/babel` script compiled in the browser on each start (~1.5 s). Release builds embed `dist/` instead, written by `scripts/build-frontend.mjs` — the `beforeBuildCommand` of `src-tauri/tauri.dist.conf.json`, which `npm run build` and `release.yml` merge via `--config` (a plain `tauri build` without it still works, just embeds the slow `src/` under the looser dev CSP). The script compiles each `.jsx` with the *vendored* Babel and the exact options Babel's script-tag loader uses (so `dist/` runs byte-identical code), turns its tag into `<script defer src="….js">` (deferred scripts run after all parser-blocking ones, in document order — the order Babel runs them in; but *before* DOMContentLoaded/load, whereas Babel runs them after, so JSX must not depend on either event or on `document.readyState`), points the React tags at the production build and drops Babel. It matches `index.html`'s tags literally and fails the build if one is missing, so keep the Babel/React tags in their plain form. It also fails on any inline `<script>` or `on*=` attribute in `dist/index.html`, and unless `tauri.dist.conf.json`'s `app.security.csp` is exactly `tauri.conf.json`'s minus script-src `'unsafe-inline'` (see the CSP bullet under *Things easy to break*). `npm test` runs the script, so CI catches a broken rewrite before a release does. `tauri.conf.json` keeps `frontendDist: ../src` because `generate_context!` embeds it at compile time — pointing it at `dist/` would make every `cargo test`/`clippy` depend on a generated folder.

The script also stamps every script `src` and stylesheet `href` in `dist/index.html`, and every `@import` in `dist/**/*.css` (a relative `@import` does not inherit its parent link's query; `layout.css` imports `_index.css`, which imports fourteen more partials), with `?v=<tauri.conf.json version>`. On Windows the WebView2 data folder (`%LOCALAPPDATA%\<identifier>\EBWebView`) survives the in-app updater, and tauri's embedded-asset responses carry no ETag/Last-Modified/Cache-Control — so a same-named URL can be served from the previous version's HTTP cache, and our load-order module graph would then run a mix of old and new files (a real failure mode after 0.4.0: folder picker opened but no tab appeared, until the cache evicted). The version changes every release, so the stamped URL always misses; the embedded-asset handler (not `assetProtocol`, which stays disabled — tauri's `tauri.rs` `get_response`) strips the query before resolving the embedded file, and the tag-matching above still sees bare paths because the stamp runs last. `tauri dev` is unaffected (it serves `src/` with bare URLs). The contract is fail-closed: stamping *parses*, it does not pattern-match — HTML tags and CSS are tokenised the way the browser/CSS tokenise them (`>` inside `title="a>b"` and the `@IMPORT`/`url()` spellings are handled; re-emitted `@import`s keep their terminating `;`, without which the whole import run would parse as one invalid rule), every `src`/`href` goes through one validating `stamp()`, and anything it cannot vouch for fails the build: a query, fragment, scheme, protocol-relative `//host`, or whitespace/control char in a URL (they hide schemes — `" https://…"`, `java\tscript:`), `&` or `\` in a URL (attribute entities like `javascript&colon;` and CSS escapes like `@\69 mport` decode to something else), a `>` or `"` in a URL value (they would end the request URL or the attribute), duplicate attributes, unbalanced tag quotes, a comment marker inside a string, an unterminated comment or stray quote between tokens, and any `@import` it cannot read (missing `;`, media/layer suffix, non-bare target). NEVER hand-add a query, fragment, whitespace, `&`, `\`, or CDN URL to an asset reference in `src/index.html`/`src/**/*.css`, and never `@import` anything but a bare app-relative quoted or `url()` path — the stamp is the only place that appends `?v=`.
